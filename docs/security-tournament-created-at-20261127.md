# Tournament creation timestamp privilege candidate
Production read-only catalog review: authenticated has a direct UPDATE(created_at) grant (grantor postgres), no table-level UPDATE, and owner/admin RLS update policy. No timestamp-specific update guard was visible. Candidate removes only this grant; authenticated browser admins are also affected. Normal start time, name, status and other column grants are unchanged. Service role retains table UPDATE. Rollback restores the same column grant. PG16/17 fixture reproduces baseline owner mutation, verifies denial after candidate, verifies normal owner/admin updates and RLS isolation, and verifies rollback. No production writes or video changes. This does not prove all RPCs are safe or eliminate quota bypass via legitimate leadership transfer (owner_id changes) or privileged administrative paths. Before deployment inspect application writes and verify current ACL again.
